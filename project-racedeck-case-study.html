Background + Problem

Where passion for F1 meets production machine learning

Why this project exists

Formula 1 has always been more than a sport to me — it is the ultimate high-stakes optimization problem: milliseconds, tyre windows, evolving tracks, and twenty drivers making interdependent strategic decisions under uncertainty. RaceDeck is where that passion meets my AI/ML craft. I wanted to answer pre-race questions the way an engineer would: with validated models, quantified uncertainty, and honest explanations — not narratives, but computed reasons backed by data and reproducible pipelines.

What needed to be solved

  • Compress chaotic pre-race context — fuel loads, track evolution, degradation, temperature, safety-car randomness — into clear decisions.
  • Predict pace, finishing order, and optimal tyre strategy across 11 raced rounds from Melbourne to Hungaroring.
  • Explain every prediction so a fan, analyst, or strategist understands the why, not just the what.
  • Enforce modeling honesty: a model ships only when it demonstrably beats its baseline.
  • Deliver results as a polished, explorable product — not a notebook.
Technical Solution

A full MLOps pipeline, gated by evidence

Corrected Feature Store

FastF1 and OpenF1 lap, telemetry, and weather data pass through fuel-load and track-evolution corrections into a versioned Parquet feature store with circuit registry, compound metadata, and deterministic manifests.

Gated Model Family

Ridge pace estimation, Monte-Carlo race simulation, dynamic-programming tyre optimization, push classification, measured overtaking recalibration, and exact linear explainability — each validated leave-one-round-out and shipped only on beating its baseline.

Weekend Briefing Product

One validated JSON document per round drives a typed FastAPI and two frontends: a deck-style live console with circuit visuals, predicted grids, strategy matrices, and registries — plus a Streamlit analytical dashboard.

Core Workflow

From raw laps to race-day briefing

Modeling Runbook

  • Ingest and validate 2026 session data with audit trails.
  • Apply fuel and evolution corrections; build versioned features.
  • Train and validate models under strict leave-one-round-out protocol.
  • Assemble one Weekend Briefing JSON per round with predictions, strategies, reasons, and metrics.

Race-Week Experience

  • Select any of the 11 rounds in the live console or dashboard.
  • Review predicted order with win, podium, and points probabilities.
  • Compare per-team tyre strategies with stint splits and undercut windows.
  • Read concise, model-derived explanations for the top contenders.
Feature Set & Capabilities

Built like a race team operates

Prediction & Strategy

  • Driver-level pace prediction at 1.33s leave-one-round-out error — roughly nine times better than the team-and-compound baseline.
  • 4000-rollout Monte-Carlo simulation producing expected positions and outcome probabilities.
  • Per-team strategy optimization with pit-loss modeling, stint constraints, and safety-car robustness.
  • Overtaking expectation recalibrated from measured on-track position changes rather than hand labels.

Transparency & Craft

  • Exact linear attribution with bucketed narratives for every top prediction.
  • Published ship-gate registry — including an honest non-shipment where the degradation model tied its baseline and priors were used instead.
  • Anti-leakage discipline, deterministic artifacts, and no retraining at serving time.
  • 42 automated tests spanning models, briefing assembly, API, and dashboard.
Tech Stack

Technologies and dependencies

ML & Data

  • Python + Scikit-learn + Pandas — Modeling, feature engineering, and analysis.
  • FastF1 + OpenF1 — Official-style lap, telemetry, and weather sources.
  • Monte-Carlo Simulation + Dynamic Programming — Race outcomes and strategy search.
  • MLflow + DVC — Experiment tracking and data versioning mindset.

Serving, Frontend & Ops

  • FastAPI + Pydantic — Typed, documented, read-only race API.
  • Vanilla JS Console + Streamlit — Broadcast-inspired experience plus analytical depth.
  • Docker + GitHub Actions — Reproducible containers and continuous validation.
  • Pytest + Ruff — Tested, lint-clean engineering.

Project Structure

Repository and file organization

Core Modules

  • src/data/ — Ingestion, validation, audit, and circuit registry.
  • src/models/ — Pace, degradation, push, simulation, strategy, explanation, and overtaking.
  • src/briefing/ — Weekend Briefing assembly runbook.
  • src/serving/ — Typed API with validated schemas.

Infrastructure

  • src/visualization/ — Live console frontend and Streamlit dashboard.
  • configs/ — Circuit and global platform configuration.
  • notebooks/ + docs/ — Executed phases, reports, and specifications.
  • tests/ + docker/ + dev/ — Quality gates, containers, and launchers.

Product Experience
